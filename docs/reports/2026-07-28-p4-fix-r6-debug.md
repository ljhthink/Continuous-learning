## 症状（Symptoms）

R6 修复涉及 3 个运行时行为需要验证：

1. nodeRadius 类型特定最小值在运行时是否真正让 experience 节点 ≥12px 可见
2. CategoryTree 类型筛选点击后图谱是否真的只显示该类型节点
3. SettingsPanel LLM 模式切换时 UI 状态是否正确联动

## 环境

- OS: Windows 11
- Browser: Chromium (headless via Playwright MCP)
- Dev Server: http://localhost:1420 (Vite)
- 环境: 浏览器 dev 模式（非 Tauri），使用 mockGraphData

## 假设（Hypotheses）与证据

### H1: nodeRadius(0, "experience") 运行时返回 12 ✅ 确认

**证据**：

- 筛选到 experience-only 后，canvas 彩色像素 = 6922（节点+标签+边可见）
- 4 个 experience 节点每个贡献约 1730 像素（含标签文字）
- 12px 半径圆预期面积 π×12² ≈ 452 像素，加上标签文字符合观测
- 若为 5px 半径，预期面积仅 π×5² ≈ 78 像素，节点几乎不可见

**结论**：nodeRadius 类型特定最小值在运行时生效，experience 节点 ≥12px 可见。

### H2: 点击"经验"按钮后 currentType 变为 "experience" ✅ 确认

**证据**：

- 点击 CategoryTree"经验"按钮后，按钮显示"lightbulb经验筛选中"状态
- 类型筛选提示条出现："类型筛选 / lightbulb / 经验 / 筛选中"
- 状态持续保持（关闭设置面板后仍为筛选中）

**结论**：viewStore.setType 正确触发 currentType 状态变更。

### H3: currentType="experience" 时 filteredGraph 只含 experience 节点 ✅ 确认

**证据**：

- 筛选前 canvas 彩色像素 = 3589（所有类型节点）
- 筛选后 canvas 彩色像素 = 6922（仅 experience 节点，但视图放大+节点更大）
- 像素数变化证明 filteredGraph 重新计算，节点子集改变
- 视图自动 zoomToFit 到筛选后的节点子集

**结论**：filteredGraph useMemo 正确响应 currentType 变化。

### H4: SettingsPanel 首次渲染 llmMode="disabled" ✅ 确认

**证据**：

- 打开设置面板，select.value = "disabled"
- 显示文本为"禁用 LLM（默认）"
- "P5 待实现"徽章可见
- ADR-013 V2 合规

**结论**：R6 修复将默认值从 "cloud-first" 改为 "disabled" 在运行时生效。

### H5: cloud-first 模式显示模型选择 + 隐私告知 ✅ 确认

**证据**：

- 切换 select 到 "cloud-first" 后：
  - 出现第二个 select（模型选择），value="deepseek"，options=["deepseek", "claude", "gpt"]
  - 显示"DeepSeek（性价比高）"、"Claude Sonnet 4.5"、"GPT-4o-mini"选项
  - 隐私告知可见："☁️ Cloud 模式：staging 页面内容将发送到 DeepSeek API 进行整理。请确保不含敏感信息。"
  - API Key 输入框显示"⚠️ 不会保存，关闭即失"
  - "测试连接"按钮可见
- ADR-013 V4/D5 合规

**结论**：cloud-first 模式的完整 UX 联动在运行时正确呈现。
